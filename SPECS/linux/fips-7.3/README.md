# FIPS canister series for Linux 7.3-rc4

The Photon OS 5.0 FIPS canister series (linux.spec Patch10000-11017, the
canister_builder sources, the jitterentropy tarball wiring) ported to the
experimental Linux 7.3-rc4 kernel of this branch.

**Not CMVP validated.** No canister of this series is published. A kernel
built with it links a canister built from this tree (the canister stamps
`FIPS_CANISTER_VERSION "7.3"` and the kernel it was really built from), which
is functionally equivalent in the sense of the equivalent-canister mode, and
carries no certificate.

## Layout

| File | What |
|---|---|
| `manifest.json` | per spec number: the file a `PatchN:`/`SourceN:` line names, the Source install name, the 6.12 patches 7.x does not need (`dropped`), the `%autopatch` ranges, and the linux-esx additions |
| `*-7.3.patch` | rebased or new patches (linux and linux-esx) |
| `*-7.3-esx.patch` | linux-esx variants of 10200/10204: its base has no RAP (Patch61/63) |
| `*-7.3.{c,h,sh}` | Sources changed for 7.x; the spec installs them under their kernel-tree names |

Patches the manifest names without a `-7.3` suffix are the 6.12 files already
on this branch; they apply to 7.3-rc4 unchanged at `--fuzz=0`.

## How it is enabled

Only by the derived wrapper (`runPh7-3-RC4.sh` v9, sharukhan profile
`7.3-rc4.json`, section `fips`) and only for a canister build:
`CANISTER_MODE` `build`, `equivalent-a` or `equivalent-b`. With the default
`none` the kernel stays FIPS-off and these files are not used. The wrapper's
FIPS editor reads `manifest.json`, rewrites the pinned specs, makes the canister
pins overridable (`canister_equivalent`/`fips_canister_override`,
`canister_stamp_real`/`fips_certified_override`, defaulting to this tree's own
linux NEVR), and restores `CRYPTO_SELFTESTS`/`CRYPTO_FIPS` and Photon's
jitterentropy settings after the 7.x config merge.

## Verification done

- Every patch applies at `--fuzz=0` on its exact parent; a replay of `%prep`
  from the pre-FIPS tree reproduces the port's common and canister_build trees
  byte for byte; `rpmbuild -bp` of the edited linux.spec and linux-esx.spec
  reproduces them as well (differences: the wrapper's `EXTRAVERSION` pin,
  install modes, the extracted canister, the version stamps).
- Built from the `rpmbuild -bp` trees with the specs' own kernel configs:
  linux (canister_build) and linux-esx (canister_usage, linking the canister
  linux built; the struct-layout match plugin reports no mismatch). Both
  booted under QEMU/KVM with `fips=1`: integrity check passes (HMAC recomputed
  and matched, identical in both flavours), 37 FIPS known-answer tests and the
  algorithm self-tests pass, user-space AF_ALG KATs pass, SHA-1 refused;
  `fips=0` boots of both pass.
- Canister reproducibility: a clean rebuild gives identical code, data and HMAC
  sections.
